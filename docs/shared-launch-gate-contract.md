# Runstir CLI·GUI 공동 1.0.0 출시 게이트와 명세 인계 계약

## 1. 첫 출시 범위와 선행 계약

첫 정식 Runstir 1.0.0은 CLI/Core·macOS GUI·로컬 앱 파일 직접 설치를 함께 제공한다. 개발 중 CLI alpha와 작은 검증 배포는 허용한다. GUI 또는 직접 설치가 미준비인 상태의 CLI 단독 정식 1.0.0은 출시하지 않는다.

공통 CLI·승인형 준비·지원 경계·GUI·직접 설치의 기존 승인 계약을 유지한다. 첫 호스트는 macOS Apple Silicon이다. Xcode 지원 하한은 27.0이다. 정확한 macOS·SDK·도구 버전과 표본은 공식 호환 조건과 선언을 조사하여 후속 명세에서 고정한다. 조사 후보는 실제 검증된 조합이 아니다.

2차 편의·로컬 앱 목록/버전 선택과 선택적 3차 팀용 연동은 첫 1.0.0의 필수 blocker가 아니다. 이 결정은 기존 CLI 구현 순서를 다시 정하지 않는다.

## 2. 출시 후보와 증거 단위 — Q1

CLI·GUI·Core의 같은 source SHA와 제품 버전으로 출시 후보를 묶는다. 후보별 source SHA·버전·CLI 배포 파일·DMG·SHA-256을 고정한다. 표본 SHA·OS/도구·선택 기기 identity·서명 방식·실행 결과를 해당 후보와 연결한다.

후보 또는 검증 입력이 바뀌면 새 기록으로 다시 검증한다. 이전 기록을 보존한다. 과거 alpha·로컬 빌드·기존 Go 성공을 새 배포 파일의 검증 증거로 대신하지 않는다. GUI 설치나 업데이트가 별도로 설치한 CLI를 자동 교체하지 않는다.

## 3. 실제 검증과 공통 증거 — Q2

공통 Core의 자동 검사 증거는 재사용한다. 네이티브 iOS·네이티브 Android·Flutter iOS/Android·React Native iOS/Android의 여섯 Simulator/Emulator 조합에서 최소 앱과 실제 OSS 앱의 정상 흐름을 CLI와 GUI로 각각 실제 검증한다.

OSS 앱은 Runstir 없이 같은 조건에서 build·install·launch·첫 화면에 도달하는 known-good baseline을 먼저 확인한다. Runstir 검증에는 별도 fresh clone을 사용한다. 준비 완료·빌드 성공·설치 완료·실행 요청·첫 화면 확인을 구분한다. 종료 코드 0만으로 첫 화면 성공을 판정하지 않는다.

개발 도구가 없는 환경과 기존 도구·기기가 있는 환경, 반복 실행을 검증한다. 기존 자원과 tracked 파일의 보존을 확인한다. 가능한 경로에 Tart를 사용하되 실제 Mac이 필요한 경로를 VM 결과로 대신하지 않는다. 기준 VM과 OCI parent를 보존한다.

공통 실패·취소·복구 시나리오는 위험 경계마다 대표 증거를 연결한다. 프레임워크·플랫폼·실행 도구·GUI에서 동작이 달라지는 경로는 각각 확인한다. 다운로드/설치 실패·취소·계획 조건 변경·동시 충돌·수동 단계 대기·예상 밖 파일 변경의 실제 실행 또는 통제 실패 증거를 남긴다. 모의 검증을 실제 설치 성공으로 세지 않는다.

실제 Homebrew 설치와 다운로드한 Developer ID 서명·공증 DMG의 설치·Gatekeeper 우회 없는 실행·수동 업데이트를 확인한다. 별도 CLI 없는 GUI 동작을 확인한다. 같은 입력의 CLI·GUI에서 검사·변경 계획·기기 후보·결과·충돌 판정이 일치하는지 확인한다.

독립 프로젝트와 동일 저장소의 서로 다른 워크트리에서 병렬 작업을 검증한다. 포트·기기·산출물·로그 분리, 충돌 차단, 작업별 취소, 창 닫기·전체 종료·실패 후 상태 재확인을 확인한다. GUI 기본 흐름과 직접 설치의 키보드·포커스·VoiceOver·승인/실패 안내를 실제로 검증한다.

직접 설치는 iOS Simulator `.app`, Android Emulator 단일 `.apk`, 대표 iOS 실기기 `.app`·`.ipa`의 Development·Ad Hoc 경로를 구분하여 검증한다. 부적합 파일·확인 불가·지원 제외 형식·기기/architecture/OS 불일치·서명/profile·안전한 IPA 압축 처리·교체/이전 버전 거부를 확인한다. 자동 재서명·기기 등록·삭제·초기화를 하지 않는지 확인한다. 교체의 표본 데이터 보존, 실패·취소·연결 해제·파일 변경 뒤 상태 재관측과 재승인을 확인한다.

iOS 직접 설치의 실기기 검증은 전체 프레임워크 실기기 행렬을 요구하지 않는다. Android 실기기는 기기 확보 후 후속 검증하며 미검증으로 표시한다. 구매·대여·클라우드 테스트를 첫 출시 필수 조건으로 만들지 않는다. 클라우드 APK 실행을 로컬 USB/RSA 경로의 증거로 세지 않는다.

자동 검사·문서·디자인으로 실제 배포 파일 설치·앱 실행·첫 화면·접근성 증거를 대신하지 않는다. 한 표본의 결과를 모든 기기·OS·프레임워크의 성공으로 일반화하지 않는다.

## 4. 출시 차단과 예외 — Q3

필수 항목의 failed·inconclusive·미검증은 출시를 막는다. 필수 요구사항의 해결되지 않은 unknown도 성공으로 세지 않는다. 데이터 손실·승인 밖 변경·서명/보안·접근성·필수 흐름의 결함은 수정하고 재검증한다.

계약이 허용한 warning과 수동 단계는 예상 결과와 잔여 조건을 증거에 기록한다. 수동 단계가 남았다는 사실을 숨기지 않는다. 필수 성공 증거가 필요한 흐름은 그 증거를 확보해야 한다. 원하는 출시 날짜만으로 필수 게이트를 면제하지 않는다. 지원 범위 변경이나 예외는 별도 결정으로 기록한다.

## 5. 명세 인계 범위 — Q4

이 티켓의 정책 질문을 모두 해결하고 계약을 main에 반영한 뒤 첫 1.0.0 범위만 `/to-spec`에 인계한다. 공통 CLI·준비·지원·GUI·직접 설치·공동 게이트의 승인 정본을 입력으로 사용한다.

2차 편의와 선택적 3차 팀용 기능은 별도 명세로 남긴다. 남은 결정이 있는 확장 지도는 OPEN으로 유지한다. 이 티켓의 종결은 확장 지도 전체 완료·구현 명세 작성 완료·제품 출시 준비 완료를 뜻하지 않는다.

## 6. 증거 보관과 공개 — Q5

공개 검증 보고서에 출시 후보·배포 파일 checksum·검증 조합·표본·시나리오별 결과·증거 링크·미검증 경계를 기록한다. 필요한 로그 발췌와 화면 증거에서 비밀값·개인 정보를 제외한다.

필요한 원본 증거는 접근을 제한한 별도 보관 위치에 둔다. 인증 정보·서명 private key·민감한 앱 환경값을 공개 보고서나 수집 증거에 넣지 않는다. 실패·판정 불가·재검증 결과를 덮어쓰지 않는다. 보관 경로·형식·누락 탐지·비식별 절차는 후속 명세에서 정한다.

## 7. 공동 공개와 완료 판정 — Q6

같은 출시 후보의 필수 CI·변경 리뷰·실제 게이트 증거를 통과한 뒤 CLI Homebrew 경로와 GUI DMG를 공동 공개한다. 비공개 후보 배포 위치와 후보 Homebrew 경로에서 먼저 실제 다운로드·설치·실행을 확인한다.

게이트 통과와 배포 작업을 구분한다. 공개 전까지 첫 1.0.0이 출시됐다고 표시하지 않는다. 공개 후 공식 다운로드·버전·파일 checksum·Homebrew가 가리키는 파일을 확인한다. 두 경로를 모두 확인한 뒤 출시 완료로 기록한다.

일부 경로만 공개됐거나 불일치가 있으면 출시 미완료로 기록하고 복구한다. 공개한 같은 버전의 파일을 다른 내용으로 조용히 교체하지 않는다. 수정 파일은 새 버전과 새 검증 기록으로 제공한다. 기존 첫 alpha archive의 ADR-0019는 과거 배포 범위로 유지한다. 이 계약 승인만으로 제품을 공개하지 않는다.

## 8. 명세 인계 산출물 — Q7

하나의 첫 1.0.0 기준 명세에 기능별 계약과 공통 경계를 연결한다. 수용 기준 표에서 각 필수 게이트를 승인 정본·검증 시나리오·표본 선정 조건·필요 증거·통과 기준에 연결한다.

정확한 SDK 버전·표본 SHA·Core API·CLI 옵션·JSON/progress·잠금·취소·fixture·배포 절차는 후속 명세에서 구체화한다. 조사 후보와 실제 검증된 조합을 구분한다. 계정·서명·수동 승인·iOS 실기기 등의 외부 입력과 Android 실기기 후속 경계를 명시한다.

미결정 정책은 명세 작성자가 대신 승인하지 않는다. 구현 티켓은 명세 이후 `/to-tickets`로 분리한다. 제품 구현·실제 설치·기기 실행·공개 배포는 별도 실행 작업이다.

## 9. 결정 종결과 다음 단계

Q1~Q7의 미결정 정책 가지는 없다. 구체 버전·표본·API·검증 절차는 승인 정책을 따르는 후속 조사와 명세의 입력이다. 이번 작업에서 제품 코드·SDK 설치·기기 실행·배포를 수행하지 않았다. 실제 출시 게이트 통과 또는 Go를 선언하지 않는다.

다음 첫 출시 작업은 계약의 main 반영 후 `/to-spec Runstir CLI·GUI 공동 1.0.0`이다. 확장 지도에는 2차 편의·로그·선택적 팀용 범위의 결정이 남아 있다.
