# PR 품질 절차

자동 체크 → 독립 리뷰와 수정 → 위험에 따른 사람 리뷰 순서로 처리한다.
CI 성공은 티켓의 실제 측정이나 독립 리뷰를 대체하지 않는다.

## 구현과 리뷰

1. 최신 `origin/main`과 변경 범위를 기록한다. 티켓의 acceptance criteria를 확인한다.
2. 필요한 변경을 구현한다. 영향받는 동작 검사를 실행한다.
3. 별도 컨텍스트의 리뷰 에이전트에게 base SHA, 변경 파일, acceptance criteria, 검증 결과를 전달한다. 리뷰 에이전트는 `docs/coding-standards.md`, `CONTEXT.md`, 관련 ADR을 읽는다.
4. 리뷰 에이전트는 확실한 문제를 직접 수정하고 커밋한다. 각 에이전트의 파일 소유권을 구분한다. 다른 작업을 되돌리지 않는다. 불확실한 문제와 범위 밖의 문제만 짧게 보고한다.
5. 수정 후 영향받는 검사를 다시 실행한다. 최종 head의 전체 diff를 검토한다. PR 본문의 근거와 위험을 갱신한다.

리뷰는 테스트가 요구 동작을 실행하는지 확인한다. fake가 실제 실패를 표현하는지 확인한다.
독립 리뷰를 실행할 수 없으면 그 한계를 PR에 기록한다. 독립 리뷰 없이 자동 병합하지 않는다.
같은 모델을 사용해도 컨텍스트는 분리한다. 서로 다른 모델을 사용하지 않았으면 그렇게 기록한다.

## CI

필수 check 이름은 `CI`다. 모든 하위 job이 성공해야 `CI`가 성공한다.

| 검사 | 확인하는 것 | 확인하지 않는 것 |
| --- | --- | --- |
| Repository hygiene | 라이선스, workflow, shell, source-only 합성 테스트 | 실제 ADB 자원과 provenance |
| macOS Swift build and tests | 잠근 의존성, 경고 없는 빌드, Swift 동작, 실제 CLI 입력 계약, 배포 archive | 실제 모바일 첫 화면과 release 승인 |
| Linux Core compile | Apple 프레임워크 없는 Core 컴파일 | Linux 제품 지원 |

source-only 테스트는 `test_*.py`를 자동 탐색한다. AST 검사는 정적 I/O 금지 제약에만 사용한다.
새 동작 검사는 interface를 실행한다. 기존 검사를 약화해서 CI를 통과시키지 않는다.
새 formatter 도입은 별도 변경으로 평가한다. 기존 전체 소스를 포맷하는 변경을 섞지 않는다.

## PR 본문과 병합

`.github/pull_request_template.md`의 Summary, Evidence, Merge Danger를 사용한다.
Summary에는 변경 흐름을 보여주는 작은 도식을 둔다. Evidence에는 실제 명령과 결과를 둔다.
문서 변경이면 기존 규칙과 새 규칙을 비교한다. 실행하지 않은 검사를 성공으로 기록하지 않는다.

| 위험 | 병합 조건 |
| --- | --- |
| two-way / narrow | 티켓 검증과 독립 리뷰 완료. 최종 head의 필수 `CI` 성공. 에이전트가 병합한다. |
| one-way 또는 broad | 위 검증 완료. 사람이 최종 head와 영향 범위를 승인한 뒤 병합한다. |

되돌리기 어려운 데이터 변경, 외부 대량 발송, 파괴적인 정리, 권한 확대는 one-way로 처리한다.
많은 프로젝트의 실행 동작이나 공개 계약을 바꾸는 변경은 broad로 처리한다.
diff 크기로 위험을 결정하지 않는다. 정책상 사람이 승인할 변경은 `ready-for-human`으로 표시한다.
현재 GitHub 보호 설정은 `CI`만 강제한다. 위 사람 승인과 독립 리뷰는 에이전트 절차다. 서버가 자동으로 강제한다고 주장하지 않는다.
최종 head SHA를 확인하고 `gh pr merge --squash --match-head-commit <SHA>`로 병합한다.
리뷰 이후 커밋이나 base가 바뀌면 영향받는 검증을 갱신한다.

## GitHub 자동 리뷰

저장소 밖의 App 설정은 workflow 삭제로 바뀌지 않는다. App 전체를 제거하면 다른 저장소도 영향을 받을 수 있다.
이 저장소의 Codex 자동 코드 리뷰와 자동 보안 리뷰는 끈다. 수동 리뷰 기능과 App 연결은 유지한다.
로컬 독립 리뷰 에이전트가 수정 커밋을 만든다. GitHub 코멘트 봇을 수정 에이전트로 간주하지 않는다.

| PR 변경 | 추가 보안 리뷰 |
| --- | --- |
| 문서, UI 표시, 보안 동작을 바꾸지 않는 일반 수정 | CI와 로컬 독립 리뷰를 적용한다. 별도 보안 리뷰는 기본으로 실행하지 않는다. |
| 권한, repository trust, 승인 검증, 비밀정보, 외부 명령, 파일 삭제, 경로 검증, dependency 또는 workflow 권한 | 별도 보안 리뷰를 수동으로 실행한다. 최종 head에서 지적을 해결하거나 근거를 기록한다. |

보안 리뷰는 필요한 PR에서 `@codex security review`로 요청하거나 로컬 보안 리뷰 스킬로 실행한다.
보안 리뷰의 성공이나 무응답을 실제 실행 안전성의 증거로 사용하지 않는다.
테스트와 티켓의 실제 검증은 별도로 완료한다.

Bugbot은 선택적인 추가 리뷰어다. 필수 `CI`나 독립 리뷰를 대체하지 않는다.
도입 시 `.cursor/BUGBOT.md`에 프로젝트 규칙을 연결한다. 리뷰가 실제로 규칙을 읽었는지 확인한다.
처음에는 수동 실행으로 실제 결함, 오탐, 수정 시간, 비용을 기록한다. 관측 결과로 유지 여부를 정한다.
Autofix 커밋도 같은 검증 절차를 거친다. Cloud Agent 접근 권한과 비용을 확인한 뒤 켠다.
Bugbot의 기본 findings 상태는 `neutral`이다. check를 필수로 등록하는 것만으로 결함이 병합을 막지는 않는다.
기능과 설정은 [Cursor 공식 문서](https://cursor.com/docs/bugbot)를 확인한다.

## 반복 지적 줄이기

반복된 지적에는 재현 사례와 원인을 남긴다. 결정적인 실패 조건이면 자동 체크로 옮긴다.
판단이 필요하면 코딩 규칙을 고친다. 정보를 못 찾았다면 AGENTS.md에 경로만 추가한다.
불필요한 탐색이나 비대한 지시문을 줄인다. 실제로 반복되지 않은 가상 문제의 체크는 추가하지 않는다.
