# macOS 승인형 도구 설치의 자동화 경계

확인일: 2026-10-09. 대상: macOS Apple Silicon. 조사 티켓: [조사: macOS 승인형 도구 설치의 자동화 경계](https://github.com/minjunkim-dev/mobile-runtime/issues/178).
이 문서는 설치 수단의 사실을 기록한다. Runstir의 설치 도구, 승인 정책, 지원 버전은 결정하지 않는다. 실제 설치와 trust, 라이선스 승인, VM 실행은 수행하지 않았다.

## 현재 계약

- 기준 소스는 `1a4ff6dc3815ab6c25df81eaef8ca37acaefe21e`다. [ADR-0009](https://github.com/minjunkim-dev/mobile-runtime/blob/1a4ff6dc3815ab6c25df81eaef8ca37acaefe21e/docs/adr/0009-activate-project-toolchains-without-provisioning.md)는 커밋된 도구 관리자 설정을 정본으로 삼는다. 설치된 도구만 활성화한다. `build/up`은 `mise trust/install/use`와 Xcode·runtime 설치를 실행하지 않는다. Corepack에는 `COREPACK_ENABLE_NETWORK=0`을 강제한다.
- [ProjectExecutionEnvironment.swift](https://github.com/minjunkim-dev/mobile-runtime/blob/1a4ff6dc3815ab6c25df81eaef8ca37acaefe21e/Sources/Core/Project/ProjectExecutionEnvironment.swift#L34)는 Git tracked mise 설정을 찾는다. 설정이 없으면 현재 PATH를 사용한다. mise 실행에는 `MISE_AUTO_INSTALL=false`를 넣는다. 새 승인형 준비 흐름은 이 코드에 구현되지 않았다.

## 요구사항과 설치 결과를 구분한다

mise는 여러 버전을 공존시킨다. `mise install`은 버전 선언을 바꾸지 않는다. `mise use`는 선언을 쓴다. `24` 같은 prefix는 정확한 버전이 아니다. 정확한 pin 또는 resolved lock이 필요하다. 이는 설치 가능성의 사실이다. Runstir가 어떤 선언을 인정할지는 별도 결정이다. [mise 도구 계약](https://mise.jdx.dev/dev-tools/index.html), [mise 시작 문서](https://mise.jdx.dev/getting-started)

mise의 기본 사용자 데이터 경로는 `~/.local/share/mise`다. 설치·plugin·shim을 여러 프로젝트가 공유한다. 경로는 환경 변수로 바꿀 수 있다. `mise where/which`는 실제 선택 경로를 반환한다. 사용자 경로라고 해서 프로젝트가 독점하는 자원은 아니다. [mise 경로](https://mise.jdx.dev/directories.html)

## 자동화 경계와 실패 후 확인

1. **설치하지 않음과 trust하지 않음은 다른 조건이다.** 현재 mise 공식 문서는 normal mode의 `mise exec/install/run`이 active config를 자동 trust한다고 설명한다. paranoid mode는 자동 trust를 끈다. ADR-0009의 trust 실패 계약과 최신 mise 문서 사이에 확인할 경계가 있다. `MISE_AUTO_INSTALL=false`의 코드만으로 trust 변경까지 막는다고 결론내릴 수 없다. 설치된 mise 버전별 동작은 재현하지 않았다. [mise trust](https://mise.jdx.dev/cli/trust.html), [mise paranoid](https://mise.jdx.dev/paranoid), [현재 코드](https://github.com/minjunkim-dev/mobile-runtime/blob/1a4ff6dc3815ab6c25df81eaef8ca37acaefe21e/Sources/Core/Project/ProjectExecutionEnvironment.swift#L80)
2. **하위 도구가 다시 설치할 수 있다.** Gradle은 toolchain resolver를 구성하면 JDK를 자동 provision할 수 있다. `org.gradle.java.installations.auto-download=false`로 끌 수 있다. 자동 설치 JDK는 Gradle User Home의 `jdks`에 남는다. daemon은 toolchain 정보를 cache한다. Corepack도 필요한 manager를 다운로드할 수 있다. 현재 Runstir는 Corepack network를 끈다. mise 플래그가 Gradle·Corepack 전체의 설치 정책을 대신하지 않는다. [Gradle toolchains](https://docs.gradle.org/current/userguide/toolchains.html#sec:provisioning), [Corepack](https://github.com/nodejs/corepack), [ADR-0009](https://github.com/minjunkim-dev/mobile-runtime/blob/1a4ff6dc3815ab6c25df81eaef8ca37acaefe21e/docs/adr/0009-activate-project-toolchains-without-provisioning.md)
3. **공유 설치 관리자는 프로젝트별 rollback이 아니다.** Homebrew Apple Silicon 기본 prefix는 `/opt/homebrew`다. 초기 설치 후 formula 설치에는 보통 sudo가 필요 없다. 일부 cask와 system service는 권한을 요구한다. `brew install` 채택 여부와 기존 formula 변경 허용 범위는 미결정이다. SDK uninstall이나 mise version 제거가 다른 프로젝트에 안전하다는 보장도 없다. [Homebrew 설치](https://docs.brew.sh/Installation), [mise 경로](https://mise.jdx.dev/directories.html), [sdkmanager](https://developer.android.com/tools/sdkmanager)
4. **완료 상태는 다시 측정한다.** mise는 `doctor`, `ls --current`, `where/which`를 제공한다. Xcode는 `xcode-select -p`, `xcodebuild -version`, `-checkFirstLaunchStatus`로 선택과 초기 구성 상태를 확인할 수 있다. SDK는 package 목록을 다시 조회할 수 있다. 이 명령들은 실패의 원인을 관측하는 수단이다. 중단된 다운로드의 안전한 resume이나 이전 상태 복구를 모든 도구가 보장한다는 근거는 확인하지 못했다. [mise 시작 문서](https://mise.jdx.dev/getting-started), [Apple command-line FAQ](https://developer.apple.com/library/archive/technotes/tn2339/_index.html), [sdkmanager](https://developer.android.com/tools/sdkmanager). `-checkFirstLaunchStatus`의 exit 의미는 로컬 `man xcodebuild`로 확인했다.

## 미확인 사항과 결정 입력

- 이번 작업은 실행 검증이 아니다. 버전별 installer idempotency, 네트워크 중단·디스크 부족·부분 추출의 recovery, shared resource ownership은 `unknown`이다. 기존 설치가 보존되는 조건과 실패 시 삭제할 범위는 이후 계약과 실제 검증이 필요하다.
- Apple의 Xcode 27 표는 확인했다. 각 native·Flutter·React Native 프로젝트가 Xcode 27에서 성공한다는 주장은 하지 않는다. Runstir의 기존 고정 검증 조합과 새 framework 검증 조합을 구분해야 한다.
- CocoaPods, Bundler, Corepack과 Gradle wrapper는 언어 runtime 설치 후에도 별도 준비 상태를 가진다. 앱 credentials와 source migration은 이 조사 범위 밖이다. Simulator runtime·AVD·system image의 생성 경계는 별도 기기 조사에서 다룬다.
- 승인 단위, installer 선택, 설정 파일 수정, global selection 변경, 약관 표시·응답, 중단 후 재시도와 제거 정책은 HITL 결정 입력이다. 이 문서는 그 결정을 확정하지 않는다.
