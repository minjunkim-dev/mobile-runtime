# #212 실제 OSS React Native 앱 후보 조사

조사일: 2026-10-10. 상태: 읽기 전용 source 조사 완료. **10개 후보의 실제 준비·빌드·설치·실행은 모두 미검증이다. 즉시 적격 후보는 확정하지 못했다.**

PrivateMind와 Expensify는 원본 Podfile에서 모든 Pods target의 deployment target을 올린다. 두 후보 모두 별도의 준비 입력 문제가 있다. 후보 SHA를 고정한 사실은 known-good 증거가 아니다.

## 범위와 판별 조건

- 선택 기준은 Xcode 27 / SDK 27, iOS 26.0 `23A343`, Android API 37 ARM64다. 기존 기기는 `Pixel_10_API_37_Play`다. system image는 `system-images;android-37.0;google_apis_playstore;arm64-v8a` revision6이며 software/headless 조건을 유지한다. [원본 실행 packet](evidence/212/attempt-04/manifest.json)을 기기 조건의 정본으로 사용한다. 앱의 compile SDK/build-tools36과 Emulator runtime37을 구분한다. 앱별 원본 선언 버전은 유지한다. 각 baseline과 후속 fresh clone에서는 같은 tuple을 사용해야 한다. [사용자 tuple 결정](https://github.com/minjunkim-dev/mobile-runtime/issues/212#issuecomment-6092021206), [#212 계약](https://github.com/minjunkim-dev/mobile-runtime/issues/212).
- SDK 27에서 resource bundle을 포함한 Pods target의 floor를 처리하는 원본 코드를 우선 찾았다. 앱 target의 `platform :ios`만으로 모든 resource bundle의 floor를 보장한다고 추론하지 않았다. SceneDelegate 부재도 iOS 26 실행 실패로 분류하지 않았다.
- RN의 resource bundle 보정은 upstream commit [`d45fc2d`](https://github.com/react/react-native/commit/d45fc2d2895057cec5acbd857a2150d10b35a378)에 있다. 이 commit의 [`updateOSDeploymentTarget`](https://github.com/react/react-native/blob/d45fc2d2895057cec5acbd857a2150d10b35a378/packages/react-native/scripts/cocoapods/utils.rb#L451-L464)는 `resource_bundle_targets`를 포함한다. 정식 v0.87.1의 같은 함수는 [native target만 순회한다](https://github.com/react/react-native/blob/a59eff64fa907ed6e919fafe6cbd26d1d54c2de3/packages/react-native/scripts/cocoapods/utils.rb#L363-L373). 따라서 최신 RN이라는 이유로 해결됐다고 판단하지 않았다. [문제 #58555](https://github.com/react/react-native/issues/58555). PR #58687의 merge를 주장하지 않는다.
- 원본 native 프로젝트, JS lock, Podfile.lock, 준비 hook, 별도 fresh clone 재현을 확인한다. 새 source patch, 버전 교체, checksum 재생성은 허용하지 않는다. [ADR-0020](adr/0020-rn-baseline-prepared-input.md)의 예외는 고정 Mattermost 입력의 Hermes checksum 1값에만 적용한다.
- [#194 후보 정본](research/cli-expansion-validation-candidates.md), [기존 #212 결과](rn-baseline-212.md), [Mattermost attempt-04](rn-baseline-212-attempt-04.md)의 실패를 보존한다. BlueWallet·Mattermost·Joplin·Rainbow의 과거 결과를 이 조사로 PASS로 바꾸지 않는다.

## 심화 1: PrivateMind 정식 1.3.0

**floor 조건은 긍정이다. frozen 준비 적격은 미확정이다.** [정식 release1.3.0](https://github.com/software-mansion-labs/private-mind/releases/tag/1.3.0)의 source SHA는 `12ac3a4a5303c13e75bf70dc332b899607571169`이다. main SHA와 다르다. tag의 package version은 `1.2.1`이다. 이를 임의로 수정하지 않는다. [tag 선언](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/package.json#L1-L18).

1. **floor:** [원본 properties](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/ios/Podfile.properties.json#L1-L8)의 app minimum은17.0이다. [원본 post_install](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/ios/Podfile#L57-L76)은 RN postinstall 뒤에 모든 Pods target의 nil/낮은 deployment target을17.0으로 바꾼다. resource bundle이 생성 Pods project의 target이면 이 loop가 포함한다. 실제 생성 project와 SDK27 빌드는 아직 확인하지 않았다. Podfile 주석의 “Xcode15+” 설명은 일반 사실로 채택하지 않았다.
2. **JS manager 진입점:** [packageManager](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/package.json#L156)는 Yarn1.22.22를 고정한다. 그러나 [원본 lock](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/yarn.lock#L1-L10)은 `__metadata.version:6`, `npm:`/`workspace:` resolution 형식이다. 원본 [.yarnrc.yml](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/.yarnrc.yml#L1-L11)은 `nodeLinker: node-modules`, `nmHoistingLimits: workspaces`와 tracked `.yarn/releases/yarn-3.6.1.cjs`를 `yarnPath`로 지정한다. 따라서 packageManager1과 Berry lock만 보고 원본 모순이라고 단정하지 않는다. 원본 Yarn 진입점과 Yarn3.6.1 위임을 실제 준비 전에 고정해야 한다. 그 진입점의 frozen graph 재현은 미검증이다. 선언 밖 Yarn 버전 교체나 lock 변환은 허용하지 않는다. [원본 CI](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/.github/workflows/test.yml#L15-L21)는 Node20과 `yarn install --frozen-lockfile`을 선언하지만 실행 성공을 조사하지 않았다.
3. **버전 교차:** [RN/native 선언](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/package.json#L90-L105), [JS RN0.83.4](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/yarn.lock#L11000-L11006), [Pods RN0.83.4](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/ios/Podfile.lock#L225-L229)는 RN0.83.4로 일치한다. Expo는 yarn에서55.0.27, Podlock에서도55.0.27이다. [JS Expo](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/yarn.lock#L6494-L6499), [Pods Expo](https://github.com/software-mansion-labs/private-mind/blob/12ac3a4a5303c13e75bf70dc332b899607571169/ios/Podfile.lock#L6-L10). ## 다음 실제 검증의 선행 조건

1. 후보 source 하나와 원본 선언 채널을 먼저 확정한다. PrivateMind의 Yarn 진입점·external path 문제 또는 Expensify의 인증·artifact·standalone 문제를 해결할 원본 입력을 기록한다. 준비 실행으로 후보 SHA를 순회하지 않는다.
2. 선언에 없는 exact 도구 버전만 별도 tuple로 고정한다. source/lock/Git 설정은 수정하지 않는다. 초기 checkout byte와 Git canonical/index audit를 보존한다.
3. 원본 manager의 frozen JS 준비와 원본 hook을 실행한다. 허용하지 않은 tracked byte/index/graph 변경이 나오면 중단한다. Plain Pod install이나 remote prebuilt 앱 다운로드를 source baseline build 성공으로 대체하지 않는다.
4. **원본 Podfile.lock 그대로 `pod install --deployment`를 통과한다.** Hermes/prebuilt/Codegen checksum drift가 나오면 증거를 남기고 중단한다. 새 후보에 Mattermost checksum 예외를 적용하지 않는다.
5. 실제 실행 lease를 받은 뒤 iOS/Android build·install·launch·첫 화면을 각각 측정한다. Simulator/Emulator는 직렬 사용한다. 원본 앱·기존 사용자 데이터·기존 GUI를 보존한다.
6. 별도 fresh clone에서 dependency와 Pods를 독립 준비한다. checksum/lock/source/도구/기기/산출물을 기록한다. 첫 clone의 Pods/node_modules/build를 복사하지 않는다. Runstir 제품의 최종 게이트는 후속 티켓으로 분리한다.

현재 결과는 후보 조사 완료다. #212의 실제 OSS 양플랫폼 known-good/fresh handoff를 완료한 결과는 아니다. 추가 입력이나 준비 정책 결정은 이 조사와 별도로 다룬다.
