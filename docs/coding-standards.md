# 코딩 규칙

이 문서는 리뷰 에이전트가 읽는다. 구현 에이전트의 전역 지시문에는 규칙 대신 문서 경로만 둔다.
도메인 용어는 `CONTEXT.md`를 따른다. 결정은 관련 `docs/adr/`를 따른다.

## 설계

- 기존 module과 표준 라이브러리를 먼저 사용한다. 실제로 달라지는 동작이 없으면 seam을 추가하지 않는다.
- interface에 동작과 실패 조건을 집중한다. 호출자에게 내부 조립 순서를 넘기지 않는다.
- deletion test로 module의 역할을 확인한다. 삭제하면 복잡성이 여러 호출자로 퍼지는 module은 유지한다.
- Core의 플랫폼 의존 분리는 Linux 컴파일로 확인한다. CLI와 GUI의 공통 판단은 EnvironmentKit에 둔다.
- 변경에 필요한 호출자, fixture, 테스트, 설정만 함께 고친다. 포맷 변경과 대규모 리팩터를 섞지 않는다.

## 검증

- 테스트는 호출자가 사용하는 interface를 실행한다. 출력, 종료 코드, 명령 실행, 파일 변화로 동작을 관측한다.
- 구현 상수 재단언과 소스 문자열 순서 검사를 동작 검증으로 사용하지 않는다.
- 외부 도구 adapter의 fake는 실패, 취소, 부분 완료를 표현해야 한다. 성공만 반환하는 fake로 실패 처리를 검증하지 않는다.
- 정적 검사는 명시적인 정적 제약에만 사용한다. 실제 실행 테스트를 대체하지 않는다.
- 버그 수정에는 수정 전 실패하는 동작 검사를 둔다. 기존 검사가 버그를 잡으면 중복 검사를 추가하지 않는다.
- 문서와 단순 설정 변경에 구현을 복제하는 테스트를 추가하지 않는다.

## 실행과 근거

- ProcessRunner seam을 사용한다. 명령 인자를 문자열로 조합하지 않는다. 종료 상태와 취소를 보존한다.
- plan approval과 repository trust를 구분한다. 실행 직전 조건과 lease 검사를 생략하지 않는다.
- 실행이 소유한 자원만 정리한다. 사용자 데이터와 기존 실행을 보존한다.
- 알 수 없는 결과는 UNKNOWN으로 기록한다. MODEL-ONLY, CI, archive 근거를 실제 기기, 지원 범위, actual readiness로 승격하지 않는다.
- 토큰, key bytes, 개인 경로의 민감한 내용은 로그와 공개 근거에서 제외한다.

## 리뷰 보고

확실한 결함은 범위 안에서 직접 수정한다. 변경 근거와 검증 결과를 짧게 남긴다.
불확실한 동작, ADR 변경, 승인 범위 확대는 구체적인 질문으로 남긴다.
스타일 취향만으로 코멘트를 만들지 않는다.
