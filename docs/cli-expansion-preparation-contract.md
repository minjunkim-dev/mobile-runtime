# Runstir 승인형 환경 준비 계약

상태: 2026-10-09 질문 1~13 사용자 승인. 승인형 환경 준비의 변경과 복구 정책을 확정했다.
티켓: [결정: 승인형 환경 준비의 변경과 복구 계약](https://github.com/minjunkim-dev/mobile-runtime/issues/182).
기준 source: `1a4ff6dc3815ab6c25df81eaef8ca37acaefe21e`.
제품 코드, 설치 또는 복구 동작을 구현·검증한 문서가 아니다.

## 첫 질문 묶음에서 확정한 정책

사용자는 2026-10-09 `그래 일단 모두 추천대로.`로 아래 다섯 권장안을 승인했다.

1. 환경 준비는 별도 `mobile setup` 명령으로 제공한다. 환경을 검사하고 부족한 항목을 준비한다. `build/up`에서 도구가 부족하면 `setup`을 안내한다.
2. 설치 버전·경로·다운로드·기기 생성 목록을 변경 계획으로 보여주고 계획 전체를 한 번 승인받는다. 저장소 신뢰·라이선스 동의·관리자 권한은 별도로 확인한다. 계획 밖 변경이 필요하면 다시 승인받는다.
3. 기존 도구와 기기를 재사용한다. 필요한 버전은 가능한 경우 나란히 설치한다. 기존 버전 삭제, 전역 설정 변경, 프로젝트 소스·lockfile 변경은 수행하지 않는다.
4. 실패·중단 뒤 완료한 설치는 보존한다. 재실행하면 실제 상태를 다시 검사하고 남은 작업을 계획한다. 설치한 SDK를 일괄 삭제하는 복구는 하지 않는다.
5. 기기 신뢰·Developer Mode·Android 디버깅 승인·Apple 계정과 개발용 서명은 안내한다. 사용자가 처리한 뒤 준비 상태를 다시 검사한다.

Flutter·React Native의 준비 범위는 iOS·Android 양쪽이다. 특정 앱 실행의 플랫폼 선택으로 이 범위를 줄이지 않는다. 플랫폼 입력 후 실행 기기 선택, 근거 있는 기본값, CLI/GUI 공용 계약은 [공통 CLI 계약](./cli-expansion-common-contract.md)을 따른다.

## 두 번째 질문 묶음에서 확정한 정책

사용자는 2026-10-09 `모두 추천대로.`로 질문 6~10의 권장안을 승인했다.

6. 프로젝트가 선언한 버전 조건을 우선한다. 조건에 맞는 설치 버전을 재사용한다. 새 설치에는 검증한 정확한 버전을 사용한다. 무조건 최신 버전을 설치하지 않는다. 지원 버전과 검증 조합은 별도 지원 경계 결정에서 정한다.
7. 지원하는 기존 도구 관리자를 재사용한다. 관리자가 없으면 Node·Ruby·JDK용으로 `mise`를 제안한다. Flutter·Android SDK는 공식 설치 경로를 사용한다. Xcode 설치와 로그인은 안내한다. 전역 `PATH`는 변경하지 않는다.
8. 가상 기기가 없으면 필요한 OS와 기기 조건을 먼저 보여준다. 승인 후 runtime을 설치하고 기기를 생성한다. 조건에 맞는 기존 기기를 재사용한다. 이름이 겹쳐도 기존 기기를 덮어쓰지 않는다.
9. 도구 설치와 프로젝트 의존성 정렬까지 완료해야 준비 완료다. 실제 빌드·앱 실행 성공은 별도로 검증한다. Flutter·React Native는 iOS·Android 양쪽의 준비 상태를 표시한다. 한쪽만 끝나면 부분 완료로 표시한다. 사람이 처리할 단계도 표시한다.
10. CLI·GUI·비대화식 실행은 같은 변경 계획을 사용한다. 비대화식 실행은 특정 계획에 대한 명시적 승인을 요구한다. 실행 전에 계획의 조건이 달라지면 멈춘다. 결과에는 실제 변경·실패·남은 작업을 기록한다.

## 세 번째 질문 묶음에서 확정한 정책

사용자는 2026-10-09 `모두 추천대로`로 질문 11~13의 권장안을 승인했다. 앞선 질문 1~10의 승인과 함께 이 문서의 전체 정책을 확정했다.

11. 소스·lockfile 변경을 요구하는 migration이나 설치 스크립트를 확인하면 자동 준비를 멈춘다. 수동 처리 방법을 안내한다. 예상 밖 변경을 발견하면 중단하고 변경을 보고한다. 사용자 파일을 자동으로 되돌리지 않는다. 임의 설치 스크립트의 부작용을 모두 사전 탐지한다고 보장하지 않는다.
12. 취소 요청 후 새 작업을 시작하지 않는다. 실행 중인 작업은 설치 도구가 지원하는 방식으로 중단한다. 안전하게 중단할 수 없으면 대기 상태를 표시한다. 완료한 설치는 보존한다. 이번 실행이 소유한다고 확인한 임시 파일만 정리한다. 공유 cache와 소유권이 불명확한 자원은 보존한다. 다운로드 이어받기는 설치 도구가 지원할 때만 제공한다.
13. 같은 설치 대상의 준비 작업을 동시에 실행하지 않는다. 충돌하면 진행 중인 작업을 안내한다. 이후 실제 상태를 다시 검사한다. 계획이 바뀌면 다시 승인받는다.

## 기존 계약과의 관계

[ADR-0009](./adr/0009-activate-project-toolchains-without-provisioning.md)의 `build/up` 도구 자동 프로비저닝 금지를 유지한다. 승인형 프로비저닝은 별도 준비 흐름에 속한다. 이번 문서로 기존 제품 동작을 변경하지 않는다.

프로젝트 의존성 정렬, 도구체인 활성화, 새 도구 프로비저닝과 앱 환경값은 각각의 경계를 유지한다. 프로젝트 소스·선언·lockfile을 바꾸는 마이그레이션은 이번 지도의 범위 밖이다. 하위 도구의 자동 다운로드·trust·파일 변경도 승인 범위에서 확인해야 할 대상이다. 승인 계획만으로 그 통제가 구현되었다고 간주하지 않는다.

## 후속 결정과 명세의 경계

이 티켓의 변경·승인·복구 정책에는 남은 질문이 없다. 세부 CLI 옵션·JSON 필드·모듈 경계는 후속 `/to-spec`에서 구체화한다. 지원 버전과 검증 조합은 [결정: 지원 경계와 새 Mac 검증 기준](https://github.com/minjunkim-dev/mobile-runtime/issues/183)에서 정한다. 구현 순서와 검증용 출시 단위는 [결정: CLI 확장의 구현 순서와 출시 단위](https://github.com/minjunkim-dev/mobile-runtime/issues/184)에서 정한다.

이 계약의 확정은 CLI 지도 전체 완료나 첫 정식 1.0.0 출시 준비 완료를 뜻하지 않는다. CLI·GUI 공동 출시 게이트와 GUI·로컬 앱 파일 설치의 상세 계약은 확장 지도에서 정한다.
